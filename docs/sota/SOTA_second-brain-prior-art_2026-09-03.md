# Prior art for a 3-D, temporally-aware, MCP-served "second brain" — state of the field as of 2026-09-03

Method. 25 web searches (the session's search cap was then exhausted) and ~110 primary-source fetches: GitHub REST API (`pushed_at`, `published_at`, `license.spdx_id`, `stargazers_count`), PyPI and npm registries for release dates, arXiv abstracts/HTML, and vendor pages. Dates are ISO; "pushed" = last commit to the default branch. Anything I could not pin to a primary source is marked UNVERIFIED. Star counts are as of 2026-09-02/03.

Target properties, numbered for the gap analysis:
P1 meaning-based hybrid retrieval (dense + lexical + graph) · P2 true interactive 3-D connectome · P3 live-updating structure that holds identity (new material is placed relative to what is known; structure biases attention) · P4 detects genuinely-new vs retelling · P5 tracks idea evolution (timeline, supersession, contradictions) · P6 a newer LLM can re-derive the sharpest articulation of a topic from the structure without re-reading everything · P7 usable by agents via MCP · P8 runs locally on Windows with optional paid APIs.

---

## A. Verdict

### A1. Nothing clonable meets 70%. The closest systems and where they stop

**1. Graphiti (Zep) — ~65%, the best mechanism, zero rendering.** Apache-2.0, 30.5k stars, `graphiti-core` 0.30.1 released 2026-09-01 (https://pypi.org/project/graphiti-core/). It is the only open system that ships P5 as a first-class data model: every edge carries `t_valid`/`t_invalid` (world time) plus `t'_created`/`t'_expired` (ingestion time); when a new fact contradicts an existing one "the system employs an LLM to compare new edges against semantically related existing edges" and "invalidates the affected edges by setting their t_invalid to the t_valid of the invalidating edge" — never deletes (Zep paper, arXiv:2501.13956, 2025-01-20, https://arxiv.org/html/2501.13956v1). Entity and edge deduplication (embedding + full-text candidate search, then an LLM resolution prompt) is a fact-grain answer to P4. Retrieval is hybrid (semantic + BM25 + graph traversal), satisfying P1. The MCP server exposes `add_memory`, `add_triplet`, `search_nodes`, `search_memory_facts`, `get_episode_entities` (provenance), `build_communities`, `summarize_saga`, `delete_*`, `clear_graph` (https://github.com/getzep/graphiti/blob/main/mcp_server/README.md) — P7 done, and `build_communities`/`summarize_saga` are a partial P6. What it lacks: no visualization at all in the OSS package (the Zep cloud has one; https://www.getzep.com/product/knowledge-graph-mcp/); the unit of knowledge is the extracted triple, so a document's *articulation* — the prose that carries an idea — is flattened into facts; the default DB is FalkorDB (Redis-based) or Neo4j 5.26+, both Docker (which on the operator's box means WSL), and the embedded Kuzu backend was marked deprecated in v0.29.2 (https://github.com/getzep/graphiti/releases); its own docs warn that "very small models frequently emit JSON that doesn't match the expected schema", so local-only extraction is fragile.

**2. Cognee — ~60%, the best local-Windows storage story.** Apache-2.0, 30.4k stars, 1.5.3 released 2026-08-23 (https://pypi.org/project/cognee/). "Local development stays fully embedded — SQLite, LanceDB, and Kuzudb — with no extra services to stand up" (README, https://github.com/topoteretes/cognee), which is precisely the no-Docker P8 profile. MCP server shipped as `cognee-mcp` (HTTP/SSE/stdio). Temporal support exists but is thinly documented: "With `temporal_cognify=True`, the engine also tags edges with their event dates, enabling temporal queries later"; "Memify goes through the graph, removes outdated nodes … and strengthens connections that appear often"; `await cognee.visualize_graph()` "can output an interactive HTML of the current knowledge graph" (all from the Cognee tutorial dated 2025-12-12, https://www.cognee.ai/blog/tutorials/beyond-recall-building-persistent-memory-in-ai-agents-with-cognee — none of these appear in the README or the llms.txt index; UNVERIFIED in current docs). The HTML visualization is 2-D. No supersession model comparable to Graphiti's bi-temporal edges; no novelty detection at the document grain. Note the 1.5.3.dev1 release (2026-08-26) removed the MCP workspace UI.

**3. claude-obsidian (AgriciDaniel) — ~55%, the best P5/P6 at the *claim* grain, but keyword retrieval and no Windows writes.** MIT, 14.6k stars, v2.1.1 released 2026-08-25 (https://api.github.com/repos/AgriciDaniel/claude-obsidian/releases). It operationalises Karpathy's LLM-wiki pattern with "source and claim provenance ledgers, deterministic linting, capability contracts" where ledgers retain "authority, freshness, support, contradiction, confidence, and review state" and "unsupported and contradictory claims remain visible" (https://github.com/AgriciDaniel/claude-obsidian). That is a working supersession/contradiction tracker (P5) and, because the LLM owns the wiki pages, a P6 loop. But retrieval is "BM25 … local and deterministic", embeddings are optional and "gated by explicit egress consent" (P1 half), visualization is Obsidian's own 2-D graph, there is no MCP (a "semantic search via qmd MCP server" item is listed as deferred), and "vault writes require WSL and fail closed with an UNSUPPORTED_PLATFORM error" on native Windows.

**4. Karpathy's llm-wiki gist — the pattern behind #3.** Published 2026-04-04, https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f. Three layers: immutable raw sources; an LLM-owned wiki of "summaries, entity pages, concept pages, comparisons, an overview, a synthesis"; a schema file (CLAUDE.md/AGENTS.md). Three operations: ingest, query, lint — lint looks for "contradictions between pages, stale claims that newer sources have superseded, orphan pages with no inbound links", and `log.md` is "an append-only record of what happened and when". This is the cleanest statement of P5+P6 in the field; it has no retrieval model (P1), no geometry (P2/P3) and no agent surface (P7).

**5. The Obsidian stack (Smart Connections + smart-connections-mcp + a 3-D graph plugin + Copilot) — ~50%, closest on P2/P7/P8, nothing on P4/P5.** Smart Connections (5,425 stars, v4.7.2 on 2026-08-06, pushed 2026-08-31) embeds locally ("Embeddings are created locally by default"), stores block-level vectors in `.smart-env/`, and in v4.7 "Connections lists can now open with a graph view" (https://github.com/brianpetro/obsidian-smart-connections/releases). Its license is *not* open source: GitHub reports NOASSERTION and the README calls it the "Smart Plugins License (source available with restrictions on competing Obsidian offerings)". msdanyg/smart-connections-mcp (MIT, 55 stars, pushed 2026-08-22) reads those same embeddings and exposes `search_notes`, `get_similar_notes`, `get_connection_graph`, `get_note_content` over MCP — "Multi-vault, block-level, 100% private" (https://github.com/msdanyg/smart-connections-mcp). Copilot (AGPL-3.0, 7.7k stars, 4.0.5 on 2026-09-01) adds the "Miyo" local semantic index and an agent mode. Four 3-D graph plugins exist (§B) but every one of them renders **wikilinks only** — none draws embedding-similarity edges in 3-D, and the two "Smart Connections Visualizer" plugins that do draw semantic edges are 2-D D3 (https://github.com/Mossy1022/Smart-Connections-Visualizer, last commit 2026-01-06).

**6. mcp-memory-service (doobidoo) — ~55%, the only OSS project with a 3-D knowledge-graph view *and* contradiction edges, but it is an agent-memory store, not a document brain.** Apache-2.0, 1.9k stars, 11.10.0 on 2026-08-28 (https://pypi.org/project/mcp-memory-service/). Ships an "Interactive 3D knowledge graph visualization (Orrery-inspired)" (added v11.3.0), a "knowledge graph with typed edges (causes, fixes, contradicts)", "NLI-based contradiction detection" (v10.67.0), and "autonomous consolidation [that] compresses old memories" with "conditional temporal decay"; SQLite backend; Windows paths documented (https://github.com/doobidoo/mcp-memory-service). Nodes are short memories, not documents or ideas; no supersession timeline; no lexical+graph hybrid documented.

**7. TrustGraph — ~55%, enterprise-heavy.** Apache-2.0, 2,663 stars, pushed 2026-08-31; v2.0 (March 2026) added PROV-O provenance triples; v2.5 on 2026-06-11 (https://trustgraph.ai/news/release-2-1/). README advertises an "interactive 3D context graph explorer with dynamic graph loading", a `trustgraph-mcp` directory, and local inference via "vLLM, TGI, Ollama, LM Studio, and Llamafiles" (https://github.com/trustgraph-ai/trustgraph). Requires a Pulsar or RabbitMQ messaging fabric under docker-compose/Kubernetes — on this machine that is a WSL deployment. No novelty/supersession semantics.

**8. LightRAG — ~50%.** MIT, 39.4k stars, 1.5.7 on 2026-09-02 (https://pypi.org/project/lightrag-hku/). Dual-level KG + vectors, "Incremental Updates & Selective Deletion" that reuse the LLM cache "to quickly rebuild the affected entities and relationships", a WebUI with "knowledge-graph exploration", and a 3-D viewer installed via `pip install "lightrag-hku[tools]"` (README; the visualizer's own README path returns 404 — its current state is UNVERIFIED). No temporal model, no MCP in the package.

**9. Microsoft GraphRAG + GraphRAG Workbench — ~45%, but the best off-the-shelf P6 and a good P2.** GraphRAG 3.1.2 released 2026-08-21, MIT (https://pypi.org/project/graphrag/), with an update workflow (`load_update_documents`); community reports are exactly "re-derive the articulation of a cluster from structure". GraphRAG Workbench (MIT, 718 stars, pushed 2026-07-18) renders entities/communities in "Next.js 16.2, React 19.2 … React Three Fiber, Three.js, d3-force-3d" with "a live constellation population while a build runs" and Ollama presets; "Chat is intentionally absent from 2.0" (https://github.com/ChristopherLyon/graphrag-workbench).

Everything else scores lower: Khoj (AGPL, 37k stars, no graph view, 2.0.0-beta.28 on 2026-03-26 while PyPI stable is 1.42.10 from 2025-07-15), SurfSense (hybrid + RRF + MCP, but Docker Desktop mandatory, BSL-licensed proprietary directory, no graph), Open Notebook (MIT, MCP, FTS + vector on SurrealDB, no graph), Reor (archived 2026-03-07), the cloud products (Tana, Mem, Recall, Reflect: no local mode; Tana and Mem have MCP/Claude connectors), InfraNodus (co-occurrence graphs with 3-D in its Obsidian plugin, MCP server, but SaaS API required), and the pure visualization tools (Cosmograph/cosmos.gl 2-D only; Nomic Atlas 2-D and cloud; Kumu 2-D no AI; Graphia 2-D/3-D desktop no AI; Kineviz 3-D commercial).

### A2. Gap analysis against the eight properties

| Property | Best existing evidence | Verdict |
|---|---|---|
| P1 hybrid dense+lexical+graph | Graphiti (semantic + BM25 + graph); Basic Memory (sqlite-vec + FTS5 hybrid, AGPL); SurfSense (semantic + FTS + RRF); txtai (sparse + dense + graph in one embeddings DB, 9.13.0 on 2026-08-27) | Solved many times; borrow, do not build. |

| P6 re-derive sharpest articulation | GraphRAG community reports; Graphiti `build_communities`/`summarize_saga`; LLM-wiki synthesis pages; Cognee memify | Pattern is well established; implementations are either triple-based (lose prose) or wiki-based (lose geometry). |
| P7 MCP | Graphiti, Cognee, Basic Memory, smart-connections-mcp, mcp-memory-service, SurfSense, Open Notebook, Supermemory, InfraNodus, Tana | Commodity; copy Graphiti's and smart-connections-mcp's tool shapes. |

Coverage estimate: the best single system (Graphiti) covers P1, P4(fact), P5, P7 fully and P3/P6/P8 partially — about 5.5/8. The best *stack* (Cognee or Graphiti as the fact layer + Smart Connections embeddings + a 3-D plugin + an LLM-wiki loop) reaches roughly 6/8 but still leaves P3 and idea-grain P4 unbuilt, and it is four codebases with three licenses.

### A3. Components worth borrowing (with URLs)

1. **Graphiti's temporal edge schema and invalidation/dedup prompts** (Apache-2.0) — https://github.com/getzep/graphiti and the paper https://arxiv.org/html/2501.13956v1. Take the four-timestamp edge, the "compare new edge against semantically related existing edges, close the validity window, never delete" rule, and the hybrid entity-resolution flow. If Docker-in-WSL is acceptable, run it as-is as the fact layer via its MCP server; otherwise re-implement the schema over Kuzu/SQLite (Cognee proves the embedded stack works).
2. **3d-force-graph + d3-force-3d** (MIT) — https://github.com/vasturiano/3d-force-graph, https://github.com/vasturiano/d3-force-3d. `graphData()` supports incremental updates; `fx/fy/fz` pin a node so "node.x [is] reset to this value and node.vx set to zero"; `numDimensions(3)`; `warmupTicks`/`cooldownTicks`/`d3AlphaDecay` control settling. For scale inside Obsidian, lift the physics worker from Fast 3D Graph (AssemblyScript Barnes-Hut octree, MIT, https://github.com/jkraccoon/obsidian-fast-graph) or New 3D Graph (Rust/WASM SIMD, MIT, https://github.com/apoo711/obsidian-3d-graph, pushed 2026-08-27).
3. **AlignedUMAP / Parametric UMAP** (BSD) as the identity-holding coordinate system — https://umap-learn.readthedocs.io/en/latest/aligned_umap_basic_usage.html and https://umap-learn.readthedocs.io/en/latest/transform.html. `relations` map identical items across slices; `alignment_regularisation` "will work harder to keep points aligned across embeddings (at the cost of the embedding quality at each slice)"; "train an initial model and then update it as we go … via the `update` method". Use 3 components, pin the aligned coordinates as `fx/fy/fz` anchors, and let the force layout only relax edges locally. This is the missing P3 primitive.
4. **Mem0's ADD/UPDATE/DELETE/NOOP loop generalised to the idea grain** (paper Apache-2.0 code, https://arxiv.org/html/2504.19413), combined with **mcp-memory-service's NLI contradiction edge** (https://github.com/doobidoo/mcp-memory-service) and **claude-obsidian's claim ledger fields** (authority, freshness, support, contradiction, confidence, review state; https://github.com/AgriciDaniel/claude-obsidian). Retrieve nearest neighbours in the aligned space, run NLI/LLM adjudication, emit a verdict with the neighbour it retells or supersedes.
5. **Karpathy's llm-wiki loop plus GraphRAG community reports for P6** — https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f (2026-04-04) and https://github.com/microsoft/graphrag (3.1.2, 2026-08-21). Wiki pages are the "sharpest articulation" artefacts; lint is the supersession pass; `log.md` is the timeline; community reports are the algorithmic fallback when no page exists yet.
6. **MCP tool shapes** — copy Graphiti's (`add_memory`, `search_nodes`, `search_memory_facts`, `get_episode_entities`, `build_communities`) and smart-connections-mcp's (`search_notes`, `get_similar_notes`, `get_connection_graph`). Reuse Smart Connections' `.smart-env/` block embeddings directly rather than re-embedding the vault.

## C. Traps and unverified claims

**License traps.** Smart Connections is source-available, not OSS (GitHub: NOASSERTION; README: "restrictions on competing Obsidian offerings") — do not vendor its code, only read its `.smart-env/` data. Copilot, Khoj, Basic Memory, Reor and the InfraNodus plugin are AGPL-3.0; Juggl and Graph Analysis are GPL-3.0. SurfSense is Apache-2.0 except `surfsense_backend/app/proprietary/` under BSL 1.1. Supermemory's repo is MIT but the self-hosted server is "licensed up to 10,000 documents" (release 0.0.7). The npm package `@cosmograph/cosmos` 3.4.1 is CC-BY-NC-4.0 while the OpenJS-hosted `@cosmos.gl/graph` 3.4.1 is MIT — same engine, different terms. Graphia's license field is null in the API (UNVERIFIED).

**Windows traps.** claude-obsidian: "vault writes require WSL and fail closed". Graphiti: FalkorDB/Neo4j only (Kuzu deprecated in v0.29.2) → Docker → WSL on this box (use the docker-wsl bridge in CLAUDE.md). SurfSense, Open Notebook, TrustGraph and Cognee's UI all assume Docker Desktop. Cognee's *library* path (SQLite + LanceDB + Kuzu) and Basic Memory, mcp-memory-service, Latent Scope and every Obsidian plugin are native-Windows clean.

**"3-D" is not "semantic".** All six Obsidian 3-D plugins (Fast 3D Graph, New 3D Graph, ReverySky, Galaxy View, the two older "3D Graph" forks) read `resolvedLinks`; none reads embeddings. The blog-style summary that Smart Connections Visualizer lets you "visualize your vault in 3D" is wrong — both Mossy1022 repos are 2-D D3. mcp-memory-service's and TrustGraph's 3-D views render memories/triples, not documents.

**Date traps in my own pipeline.** GitHub release pages omit the year for current-year releases, and the fetch summariser invented years four times (Graphiti "2024", GraphRAG "2024", Khoj "2025", Kotaemon "2025"). I replaced every such date with the REST API `published_at` or the PyPI "Released" date; those are the dates in §B. Consequence: the third-party claim that Kotaemon has been "dormant since May 2025" (ai-radar.aoe.com, July 2026) is false — v0.12.0 was published 2026-05-31 and the repo was pushed 2026-07-14. txtai's PyPI upload time could not be read (GitHub API: 2026-08-27). TrustGraph publishes tags, not releases; its 2.9.2 PyPI date could not be read.

**Vendor/marketing claims not independently verified.** Tana's "updates the record … de-duplicates" and MCP proposal-review flow (Tana blog, 2026-07). Supermemory's "Contradictions are resolved automatically" (README; no algorithm described). Copilot's marketing page says its agent "flags contradictory claims" — no mechanism documented. Mem's "Claude Connector" appears only as a blog headline. Kineviz 3-D is inferred from screenshots. Cognee's `temporal_cognify`/`memify`/`visualize_graph` are documented only in a 2025-12-12 blog post, not in README or the docs index. Mem0's OpenMemory local MCP server: the `openmemory/` path returns 404 and the docs overview no longer mentions it — status UNVERIFIED. Khoj's docs landing page mentions no MCP; treat "Khoj has MCP" as UNVERIFIED.

**Not evaluated** (search cap reached): Memgraph Lab's 3-D view, Anytype, AFFiNE, Heptabase, Capacities, mymind, Saner, NotebookLM's mind map (Wikipedia confirms only Data Table 2025-12 and Short Video Overviews 2026-07), the "Memory Store" MCP named in the Graphlit survey, ttommyth/rag-memory-mcp (vector+KG hybrid, MIT, per mcp.directory 2026-06), Letta/MemGPT, MemOS.

**Design traps the literature warns about.** Force layouts are not stable across runs; UMAP `transform()` "expect[s] the overall distribution … to be consistent between the training and testing data" — with a drifting personal corpus you need AlignedUMAP or Parametric UMAP, and alignment costs per-slice quality. "Is this outdated?" cannot be read from model confidence: temporal drift is "orthogonal to both correctness and uncertainty", so "any method operating on correctness or uncertainty signals is therefore blind to drift by construction" (arXiv:2605.09195) — supersession must be explicit metadata, as in Graphiti. Vanilla RAG "struggle[s] under this setting, exposing … catastrophic forgetting and temporal inconsistency" (arXiv:2604.05096). When benchmarking dense vs lexical retrieval on your own notes, pin the BM25 floor by construction or the "lift" is an artefact of entity-token overlap (arXiv:2605.29630); the same paper finds MiniLM-384 more consistent than BGE-large, so do not assume a bigger embedder helps. Graphiti's own docs: small local models "frequently emit JSON that doesn't match the expected schema" — budget a paid extraction model for the fact layer and keep local models for embedding and rendering-side labelling.

**Bottom line.** Retrieval (P1), rendering (P2), MCP (P7) and local storage (P8) are commodities with MIT/Apache parts. Fact-grain supersession (P5) and fact-grain dedup (P4) are solved by Graphiti/Mem0 and should be borrowed, not rewritten. The unbuilt core — a semantic 3-D layout that holds identity as material arrives and biases what an agent attends to, plus idea-grain novelty verdicts over prose — has no prior implementation I could find as of 2026-09-03; the nearest primitives are AlignedUMAP `update`, d3-force-3d pinning, HippoRAG's PPR, and A-MEM's memory evolution.
